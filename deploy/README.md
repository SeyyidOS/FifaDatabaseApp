# Self-hosted deployment

Runs FIFA Manager on this server behind the shared Caddy proxy (the one that serves MLflow), at
**https://fifa.173.249.40.69.sslip.io**. Caddy handles HTTPS; this folder only adds a site block.

| Container  | What it is                                                     | Networks                      |
|------------|-----------------------------------------------------------------|-------------------------------|
| `fifa_web` | nginx: the built React app and the `/api` proxy                 | `mlflow_net`, `fifa_internal` |
| `fifa_api` | the FastAPI backend (`backend/`)                                | `fifa_internal` (no internet) |
| `fifa_db`  | Postgres 16, data in `/root/programs/fifa-app/pgdata`           | `fifa_internal` (no internet) |

```bash
deploy/deploy.sh                 # publish or update by hand (backs up first; safe to re-run); normally auto-deploy.sh does it
deploy/deploy.sh --backup        # gzipped SQL dump into /root/programs/fifa-app/backups
deploy/deploy.sh --passwords     # first passwords of the "main" board (the original group)
deploy/deploy.sh --admin-key     # server admin key: works as admin on every board
deploy/deploy.sh --import FILE   # first run only: load a plain SQL dump into the empty database
deploy/deploy.sh --remove        # unpublish; containers go, data stays
```

## Boards and access

Anyone can create a board from the home page. Each board has its own players, matches, standings,
K-factor and club ratings (one list per game, e.g. FC26 and FC27). A board has two passwords:

- the **board password**, shared with the group: view everything, add players, log matches;
- the **admin password**: archive or delete, rename, change the K-factor and the passwords.

Signing in returns a token the browser keeps ("Remember this device"), so a device stays signed in.
Changing a password in Settings signs out the devices that used the old one. Wrong passwords are
limited to 10 per 15 minutes per address, new boards to 5 per hour.

The data from before boards existed lives in the board `main` (`#/b/main`); old links redirect there.

## Secrets

`/root/programs/fifa-app/secrets.env` (mode 600; missing values are generated by the script):

| Variable                       | Purpose                                                        |
|--------------------------------|----------------------------------------------------------------|
| `POSTGRES_PASSWORD`            | database password                                              |
| `SECRET_KEY`                   | signs device tokens; changing it signs every device out        |
| `ADMIN_KEY`                    | server admin key (`X-Admin-Key` header), admin on every board  |
| `LEGACY_BOARD_PASSWORD`        | first board password of `main` (used once, by the migration)   |
| `LEGACY_BOARD_ADMIN_PASSWORD`  | first admin password of `main` (used once, by the migration)   |

## Continuous deployment

The server publishes `main` by itself: a systemd timer runs [`auto-deploy.sh`](auto-deploy.sh) every
minute in a clean clone at `/root/programs/fifa-app/repo` (never in a working copy). When `main` has
a new commit and its GitHub Actions checks (`backend`, `frontend`) have passed, it runs `deploy.sh`
for that commit: database backup, build, restart, smoke test. If that fails, the commit that was live
before is published again. A commit whose checks or deploy failed is skipped; the next commit on
`main` is tried as usual. It only reads from GitHub (the repository is public), so no credentials for
it are stored here.

```bash
/root/programs/fifa-app/repo/deploy/auto-deploy.sh --status   # live commit, waiting, skipped, last log lines
journalctl -u fifa-auto-deploy -n 50                          # the timer's runs
systemctl list-timers fifa-auto-deploy.timer                  # when it runs next
```

Set up once (already done on this server):

```bash
git clone https://github.com/SeyyidOS/FifaDatabaseApp.git /root/programs/fifa-app/repo
cp /root/programs/fifa-app/repo/deploy/systemd/fifa-auto-deploy.* /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now fifa-auto-deploy.timer
```

To stop publishing for a while: `systemctl stop fifa-auto-deploy.timer` (`start` to resume). To go
back to an older commit, revert it on `main` through a pull request; restoring the database from
`backups/` is manual (`gunzip -c FILE | docker exec -i fifa_db psql -U fifa -d fifa_db` into an
empty database).
